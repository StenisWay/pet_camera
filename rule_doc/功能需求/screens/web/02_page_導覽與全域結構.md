# 畫面規格書(Web):頂部導覽與全域結構

| 項目 | 內容 |
|---|---|
| 平台 | Web(RWD,依視窗/螢幕尺寸自適應;手機作業系統另行導向,見第 0 節) |
| 對應功能規格書 | 無獨立功能規格,純導覽結構定義 |
| 適用範圍 | 整個 Web 站台,含登入前(見 `01_page_登入註冊忘記密碼.md`)與登入後所有畫面 |

## 0. 手機作業系統偵測與導向(優先於任何畫面渲染)

判斷依據是**作業系統,不是螢幕寬度**。任何路由(含尚未登入的登入/註冊頁)載入時,前端先偵測 User-Agent:

- User-Agent 判定為 iOS 或 Android 手機 → 不渲染任何 Web 畫面,改顯示單一導向頁:App 圖示 + 「請下載 App 使用」文案 + 依作業系統顯示對應的 App Store / Google Play 下載連結。此導向頁沒有登入表單,也沒有任何 Web 功能入口。
- 其餘一律視為桌面瀏覽器(含平板、筆電、桌機,不論視窗或螢幕尺寸)→ 正常渲染 Web 畫面(本文件其餘章節),並套用 RWD 依可用寬度調整版面(見第 1、3 節)。

**RWD 不是「行動版網頁」的替代方案**:兩者是不同的機制——RWD 解決的是桌面瀏覽器視窗/螢幕尺寸不一的排版問題(縮小視窗、筆電小螢幕、外接大螢幕都要能用),手機作業系統偵測解決的是「手機一律用 App,不give 網頁版入口」的產品範圍決定(見 `00_PRD_需求書.md`「平台範圍」)。不要把兩者混為一談,也不要因為做了手機導向就省略 RWD。

## 1. 導覽結構

Web 不採用底部 Tab bar(桌面瀏覽器慣例是頂部導覽,而非行動裝置的底部導覽)。登入成功後,畫面頂部固定一條導覽列,左側為 Logo,右側為三個導覽項目 + 使用者選單:

| 導覽項目 | 對應畫面規格書 | 說明 |
|---|---|---|
| 首頁 | `03_page_首頁.md` | 裝置列表,登入後預設頁面 |
| 相簿 | `05_page_相簿.md` | 使用者保存的照片/剪輯 |
| 會員 | `06_page_會員資料.md` | 帳號與裝置管理入口 |

每個項目對應一個獨立路由(如 `/dashboard`、`/albums`、`/account`),可直接以網址列輸入或加入書籤,不同於 App 的 Tab 是 App 內部狀態。

## 2. 非導覽列畫面(獨立路由,頂部導覽列仍保留)

- `04_page_攝影機畫面.md`(由首頁裝置卡片點擊進入,路由如 `/dashboard/devices/{id}`)。與 App 不同,Web 版此畫面**不隱藏**頂部導覽列,只在導覽列下方以麵包屑顯示「首頁 > {裝置名稱}」,方便直接切換回其他導覽項目而不需要按「返回」。

## 3. 規則

- 切換導覽項目時各頁面保留自身捲動位置與篩選狀態,與 App 版行為一致。
- 推播通知(Web Push)點擊後的 deep link(見 `../../09_spec_推播通知.md`)導向攝影機畫面對應路由,頂部導覽列維持顯示,不強制跳轉導覽狀態。
- 桌面版寬螢幕下,導覽列固定於頁面頂部(sticky),捲動內容時導覽列不隨之捲走。
- 導覽列本身依 RWD 斷點調整:寬螢幕顯示完整文字 + 圖示,視窗縮小到中等寬度(如筆電、平板橫向)時導覽項目改為僅圖示,不隱藏或收進漢堡選單——三個導覽項目數量少,沒有必要為了窄一點的桌面視窗犧牲可見性。
