## 1. 畫面用途

使用者尚未登入時的入口流程,完成後進入首頁(見 `03_page_首頁.md`)。以 iOS 或 Android 手機瀏覽器造訪時,連本頁的登入表單都不會渲染,直接被導向 App 下載頁(見 `02_page_導覽與全域結構.md` 第 0 節,優先於本文件所有內容;判斷依據是作業系統,不是螢幕寬度,平板/筆電正常看到本頁並套用 RWD)。Web 依 `02_spec_登入註冊與密碼重設.md` 第 2.3.1 節取得較短效期的 access token,過期由 refresh token 靜默換發,一般情況下使用者不會頻繁看到此流程。

## 2. 畫面組成與導覽動線

```
[登入頁 /login] --點擊「註冊」--> [註冊頁 /register] --註冊成功--> [登入頁]
[登入頁] --點擊「忘記密碼」--> [忘記密碼頁 /forgot-password] --送出--> [忘記密碼已送出提示]
[Email 內連結] --開啟--> [重設密碼頁 /reset-password?token=...] --重設成功--> [登入頁]
[登入頁] --登入成功--> [首頁 /dashboard]
```

每個畫面各自為獨立路由,並非 App 版的全螢幕堆疊;版面為置中卡片(寬度約 400px),背景為滿版留白或品牌背景,符合桌面瀏覽器慣例。可用瀏覽器的上一頁/下一頁在登入、註冊、忘記密碼之間切換。

### 2.1 登入頁

- 元素:Email 欄位、密碼欄位、登入按鈕、分隔線(「或」)、「使用 Google 繼續」按鈕、「使用 Apple 繼續」按鈕、「忘記密碼」文字連結、「還沒有帳號?註冊」文字連結。
- 支援鍵盤 Enter 直接送出表單。
- 第三方登入按鈕點擊後喚起對應 provider 的 JS SDK 流程(彈出視窗或導轉後導回),行為與錯誤提示見 `../../02_spec_登入註冊與密碼重設.md` 第 2.7 節,本文件不重複定義。

### 2.2 註冊頁

- 元素:Email 欄位、密碼欄位、密碼強度提示文字(即時顯示是否符合規則)、註冊按鈕、分隔線(「或」)、「使用 Google 繼續」按鈕、「使用 Apple 繼續」按鈕、「已有帳號?登入」文字連結。
- 欄位規則與即時驗證訊息見 `../../02_spec_登入註冊與密碼重設.md` 第 2.1 節,本文件不重複定義。
- 註冊成功導回登入頁,不自動登入。
- 本頁的第三方登入按鈕與登入頁為同一組操作(建立新帳號或登入既有帳號皆由後端依 2.7 節規則判斷),UI 上不需與登入頁區分。

### 2.3 忘記密碼頁

- 元素:Email 欄位、送出按鈕。
- 送出後畫面切換為單一提示文字(「若該 Email 存在,重設連結已寄出」)+「返回登入」按鈕,不停留在表單狀態。

### 2.4 重設密碼頁

- 由 Email 內連結直接開啟瀏覽器網址(`/reset-password?token=...`),不需先安裝或開啟任何 App。
- 元素:新密碼欄位、確認新密碼欄位(需一致,規則見 `../../02_spec_登入註冊與密碼重設.md` 第 2.1 節)、送出按鈕。
- Token 無效/過期時,整頁替換為錯誤狀態(見功能規格書 AUTH_007),不顯示表單。
