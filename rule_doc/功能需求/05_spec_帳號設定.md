## 1. 使用者故事

1. 作為使用者,我想在已登入狀態下修改密碼。
2. 作為使用者,我想刪除帳號。

## 2. 功能說明

### 2.1 修改密碼 / 設定密碼

`users.password_hash` 不為 `null`(已設定過密碼)時顯示「修改密碼」表單:需輸入目前密碼與新密碼,驗證目前密碼正確且新密碼符合密碼規則(見 `02_spec_登入註冊與密碼重設.md` 第 2.1 節)後才更新。更新後不強制登出當前 session,但**撤銷該帳號其他所有未撤銷的 `refresh_tokens`**(保留當前這一筆)。

理由:使用者改密碼的常見動機就是懷疑帳號外洩,若不撤銷其他 session,攻擊者持有的 refresh token 仍可繼續換發 access token,改密碼等於沒有效果。當前 session 保留是為了避免使用者剛改完密碼就被踢回登入頁。

**已知限制**:App 平台不使用 refresh token,其 access token 效期長達 180 天且刻意不做撤銷(見 `02_spec_登入註冊與密碼重設.md` 第 2.8 節),因此改密碼**無法**使既有的 App token 失效。這是 2.3.2 節「長期保持登入」設計的代價,在此明確記錄為接受的風險,而不是實作遺漏。

`users.password_hash` 為 `null`(僅透過第三方登入建立、尚未設定過密碼,見 `02_spec_登入註冊與密碼重設.md` 第 2.7 節)時顯示「設定密碼」表單:僅需輸入一次新密碼,不需輸入目前密碼,驗證符合密碼規則後寫入 `password_hash`。設定成功後,該帳號之後可改用 email/密碼登入,亦仍保留原第三方登入方式。

### 2.2 刪除帳號

破壞性操作,需二次確認。`users.password_hash` 不為 `null` 時以輸入目前密碼確認;為 `null`(僅第三方登入、未設定密碼)時改以輸入帳號 Email 文字比對確認,不符合時顯示 `VAL_001`(定義於 `10_錯誤處理與狀態規範.md` 第 3 節)。確認後依 `01_資料模型與儲存規格.md` 第 6 節串聯清除,再刪除帳號本身,並清除本機 token 導向啟動頁。

**串聯順序與失敗處理**:Auth 服務不直接寫入其他服務擁有的資料表(違反 `13_ADR_微服務與三節點部署.md` 第 1 節的邊界原則),改以內部端點依序呼叫,全部成功才刪除 `users`:

1. `DELETE /internal/users/{user_id}/devices`(Device 服務,見 `04_spec_裝置管理.md` 第 3 節)——刪除名下所有裝置的事件與 R2 物件,裝置重置為 `pending`。
2. `DELETE /internal/users/{user_id}/media`(Album 服務,見 `12_spec_相簿與雲端匯出.md` 第 3 節)——刪除相簿項目與對應 R2 物件。
3. 於單一交易內刪除 Auth 自己擁有的 `refresh_tokens`、`password_reset_tokens`、`oauth_identities`,以及由外鍵 `ON DELETE CASCADE` 帶走的 `push_tokens`、`google_drive_credentials`,最後刪除 `users` 紀錄。

任一步驟失敗即整個操作失敗,回 `SRV_002`,**不刪除 `users`**,使用者帳號維持可用,可重試。這符合 `13_ADR_微服務與三節點部署.md` 第 4 節「Auth 一律選一致性(C)」——寧可刪不掉,也不要留下一個登不進去卻還有資料殘留的帳號。

兩個內部端點都要求**冪等**:第 1 步成功、第 2 步失敗時,使用者重試會重新呼叫第 1 步,此時名下已無裝置,必須視為成功而非錯誤。由於第 1、2 步已經把資料刪掉,重試前的中間狀態是「帳號還在但裝置與相簿已清空」——這是刻意選擇:可重試且最終一致,優於為了原子性而引入跨服務分散式交易(該複雜度的否決理由見 ADR 第 5 節)。

## 3. API 介面

| Method | Path | 說明 |
|---|---|---|
| PATCH | `/auth/password` | 修改密碼(`password_hash` 已存在時需附目前密碼)或設定密碼(`password_hash` 為 `null` 時免附) |
| DELETE | `/auth/account` | 刪除帳號(`password_hash` 已存在時需附目前密碼,為 `null` 時需附帳號 Email 作為確認文字) |

## 4. 讀取狀態

| 階段 | UI 呈現 |
|---|---|
| 修改密碼送出後 | 送出按鈕 disable + spinner |
| 刪除帳號確認後 | 確認按鈕 disable + spinner,完成後清除本機 token 並導向啟動頁 |

## 5. 錯誤碼

| 錯誤碼 | HTTP Status | 說明 | 使用者訊息 | 呈現方式 |
|---|---|---|---|---|
| AUTH_008 | 401 | 修改密碼時目前密碼輸入錯誤(僅 `password_hash` 已存在的帳號適用) | 目前密碼錯誤 | Inline 於修改密碼表單 |
| AUTH_009 | 401 | 刪除帳號時密碼確認錯誤(僅 `password_hash` 已存在的帳號適用) | 密碼錯誤 | Inline 於刪除帳號確認框 |

刪除帳號的串聯清除中,任一內部端點呼叫失敗時回全域 `SRV_002`(定義於 `10_錯誤處理與狀態規範.md` 第 3 節),前端顯示「服務暫時無法使用」並提供重試。

修改密碼時,新密碼不符強度規則沿用 `AUTH_006`,定義見 `02_spec_登入註冊與密碼重設.md` 第 5 節,本文件不重複列出。僅第三方登入、`password_hash` 為 `null` 的帳號,刪除帳號時 Email 確認文字不符沿用全域 `VAL_001`,定義見 `10_錯誤處理與狀態規範.md` 第 3 節。

## 6. 驗收標準

- [ ] 使用者輸入正確目前密碼與符合規則的新密碼後,可成功修改密碼
- [ ] 目前密碼輸入錯誤時顯示 AUTH_008
- [ ] 新密碼不符規則時顯示 AUTH_006
- [ ] 僅第三方登入建立、尚未設定密碼的帳號顯示「設定密碼」表單,不需輸入目前密碼即可設定成功
- [ ] 使用者可刪除帳號,刪除後所有裝置與事件資料一併清除且無法再登入
- [ ] 刪除帳號時密碼確認錯誤顯示 AUTH_009
- [ ] 僅第三方登入、未設定密碼的帳號刪除時改以 Email 文字確認,不符合時顯示 VAL_001
- [ ] 修改密碼成功後,該帳號其他 Web session 的 refresh token 失效,當前 session 仍可用
- [ ] 刪除帳號時 Device 或 Album 內部端點失敗,回 SRV_002 且帳號仍可登入
- [ ] 刪除帳號重試時,已無裝置的內部端點呼叫視為成功(冪等)
