# 錯誤處理與狀態規範

| 項目 | 內容 |
|---|---|
| 適用範圍 | 所有功能規格書(F0~F6)共用此規範,各功能規格書僅定義自身專屬的錯誤碼 |

## 1. UI 狀態模型

任何資料驅動的畫面必須實作以下四種狀態,不可有「卡在中間」的未定義狀態:

| 狀態 | 規則 |
|---|---|
| Loading | 首次載入用 skeleton 佔位畫面;分頁載入更多用列表底部小型 spinner;按鈕觸發的操作用「按鈕本身 disable + spinner」,不整頁 loading |
| Empty | 資料為空時顯示對應插圖與文案,不得顯示空白畫面 |
| Error | 依第 2 節分類顯示,必須提供對應的復原路徑(重試/導向/修正輸入) |
| Loaded | 正常渲染資料 |

## 2. 錯誤顯示分類

| 類型 | 使用時機 | 呈現方式 |
|---|---|---|
| 全頁錯誤(Full-page) | 頁面主要內容完全無法載入 | 整頁替換為錯誤圖示 + 訊息 + 重試按鈕 |
| 內嵌錯誤(Inline) | 表單欄位驗證、單一列表項目操作失敗 | 錯誤訊息顯示於對應元件下方或旁側,不影響頁面其他部分 |
| Toast/Snackbar | 背景操作失敗(如標記已讀失敗),不阻斷使用者當前流程 | 畫面底部短暫提示,3 秒後自動消失 |
| 阻斷式對話框(Modal) | 需要使用者立即做決策或已無法繼續操作(如登入已失效) | 彈出對話框,需使用者確認或導向後才可關閉 |

**重試規則**:網路逾時、5xx 伺服器錯誤一律提供「重試」按鈕;4xx 使用者輸入類錯誤不提供純重試,需引導修正輸入。

## 3. 全域錯誤碼

以下錯誤碼適用於所有功能,各功能規格書另有專屬錯誤碼(前綴依功能區分:`STREAM_`、`EVENT_`、`TIMELINE_`、`PUSH_`、`AUTH_`、`DEVICE_`、`CLIP_`、`SCREENSHOT_`、`DRIVE_`)。

| 錯誤碼 | HTTP Status | 說明 | 使用者訊息 | 呈現方式 |
|---|---|---|---|---|
| AUTH_001 | 401 | 未登入或 token 無效 | 請重新登入 | 阻斷式,導向登入頁 |
| AUTH_002 | 401 | Token 已過期 | 登入已逾時,請重新登入 | 阻斷式,導向登入頁 |
| NET_001 | - | 裝置無網路連線 | 目前無網路連線 | 全頁或 Toast + 重試 |
| SRV_001 | 500 | 伺服器內部錯誤 | 系統發生錯誤,請稍後再試 | Toast + 重試 |
| SRV_002 | 503 | 服務暫時無法使用 | 服務暫時無法使用 | 全頁錯誤 |
| RATE_001 | 429 | 請求過於頻繁 | 操作過於頻繁,請稍後再試 | Toast |
| VAL_001 | 400 | 輸入格式錯誤 | 依欄位顯示對應訊息 | Inline |

`RATE_001` 的限流計數以共用 Redis 實作(`ratelimit:{user_id 或 ip}:{endpoint}`,見 `01_資料模型與儲存規格.md` 第 7 節)。Redis 暫時無法存取時採 fail-open,直接放行請求,不因限流機制本身故障而阻斷全站服務,詳見 `13_ADR_微服務與三節點部署.md` 第 4 節。
