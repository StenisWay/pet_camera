# 語法與渲染地雷

出現在這裡的每一條都會讓圖「看起來沒問題但其實壞了」，或直接渲染失敗。

---

## 中文

- **PlantUML 預設字型不一定有中文字**，渲染出來是方框或亂碼。指定字型：
  ```
  skinparam defaultFontName "Noto Sans CJK TC"
  ```
  伺服器端渲染（plantuml.com）通常沒事，本機 java 渲染最常中槍。
- 中文標籤**不需要**引號，但含空白或標點時加引號比較安全：`class "訂單明細" as OrderLine`。
- 中文寬度是英文的兩倍，`maxMessageSize`／`nodesep` 的預設值是照英文調的，
  **中文圖要把這些值抓得比英文圖大**，否則字會擠出方框。
- 類別名用英文、顯示名用中文（`class Order as "訂單"`）比全中文好維護，
  因為關係線引用的是類別名。

---

## 跳脫字元

| 想打 | PlantUML | 說明 |
|---|---|---|
| 換行 | `\n` | 標籤內換行 |
| `\|` | `\\|` | 直接打會被當表格分隔 |
| 引號 | `\"` | 標籤內的引號 |
| `<` `>` | `&lt;` `&gt;` | 泛型 `List<String>` 要跳脫，否則被當 HTML 標籤吃掉 |

`.drawio` 那邊的規則不一樣：值寫在 XML 屬性裡，`&` `<` `>` `"` 都要 escape
（`drawio_gen.esc()` 已代勞）。**注意 XML 屬性值裡的實體換行在解析時會被正規化成空白**——
所以用 `xml.etree` 讀回來的 label 拿不到原本的行數，別用它判斷排版高度。

---

## `linetype ortho` 崩壞

`skinparam linetype ortho` 在這些情況會畫出詭異的線：

- 節點間距太小（`nodesep < 40`）：線貼著方框走，多重性標籤壓在框上。
- 有自我關聯（`A -- A`）：直角線繞不出來，會變成一團。
- 混用 `-up->` 與 `-down->` 在同一組節點之間：線可能重疊成一條。

出問題就改回預設或 `polyline`。**ortho 是為了好讀，不是為了好看**，讀不了就別堅持。

---

## 多重性標籤重疊

水平關聯線上的兩端標籤容易黏在一起（`0..*` 和 `1` 變成 `0..*1`）。

- 帶多重性的關聯**盡量走垂直**。
- 一定要水平就把 `nodesep` 加大到 50+。
- 檢查方式只能目視——渲染器不會報錯，量測腳本也抓不到。

## 常見錯誤訊息

| 訊息 | 原因 |
|---|---|
| `Syntax Error?` 指向某行 | 多半是前一行沒收尾（`{` 沒關、`@enduml` 漏掉） |
| 圖只畫出一半 | 中間某行語法錯，PlantUML 會安靜地停在那裡 |
| `Cannot find Graphviz dot` | 類別圖／狀態圖需要 Graphviz，循序圖不用；裝 `graphviz` 即可 |
| 節點莫名多出來 | 打錯字造成新節點（`Ordr -- Product` 會憑空生出 `Ordr`）——**沒有連線的孤立節點多半就是打錯字** |

最後一條值得特別警覺：PlantUML 不會因為你打錯類別名而報錯，它會直接生一個新類別。
交付前檢查清單裡「沒有孤立元素」這條，抓的就是這個。

## .drawio 專屬地雷

- **邊的 id 是自動產生的 `e0, e1, e2...`**，節點 id 千萬別取名 `e1`，會撞成重複 id
  而讓檔案安靜地壞掉（用 `err1`、`noteWeb` 這種前綴）。
- **容器要在它的內容物之前宣告**，否則後畫的容器會蓋住裡面的元件（mxGraph 依宣告順序決定 z-order）。
- **waypoints 的每一段都要軸對齊**（每個點跟前一點共用 x 或 y）。斜線段不會被
  `check_overlaps` 檢查到——它只驗水平／垂直段，斜線是檢查的盲點，會安靜地通過。
- 結構驗證（`drawio_gen.validate_file`）與版面驗證（`check_layout.py`）是兩件事，
  兩個都要跑。檔案結構完全正確、線畫在別人的字上，是可以同時成立的。
